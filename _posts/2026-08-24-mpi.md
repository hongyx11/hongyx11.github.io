A cluster joins many nodes, but memory is not shared across them. MPI programs launch processes called ranks; each rank owns local memory and exchanges data explicitly.

## The basic shape

```cpp
#include <mpi.h>
#include <iostream>

int main(int argc, char** argv) {
  MPI_Init(&argc, &argv);

  int rank = 0;
  int size = 0;
  MPI_Comm_rank(MPI_COMM_WORLD, &rank);
  MPI_Comm_size(MPI_COMM_WORLD, &size);

  std::cout << "rank " << rank << " of " << size << '\n';

  MPI_Finalize();
}
```

Build with the MPI compiler wrapper and launch through the cluster's supported command:

```bash
mpicxx -O3 -std=c++20 hello.cpp -o hello
srun --ntasks=4 ./hello
```

Some systems use `mpirun` or `mpiexec`; follow local guidance so the launcher integrates with the scheduler.

## Decompose data and work

Suppose a vector of length $N$ is split across $P$ ranks. Rank $r$ owns a contiguous interval, computes a local result, and participates in a collective operation such as `MPI_Reduce` or `MPI_Allreduce`.

The decomposition should balance work and minimize the data crossing process boundaries. Sparse matrix decompositions are harder because rows and columns can have irregular structure and computation.

## Communication has a model

A simple message model is

$$T_{message} \approx \alpha + \beta n,$$

where $\alpha$ represents latency, $\beta$ is time per byte, and $n$ is the message size. Many tiny messages pay latency repeatedly; one enormous message may delay useful work or require extra memory.

Collectives express common patterns more clearly than hand-written point-to-point code and allow the MPI implementation to choose optimized algorithms.

## Avoid common errors

- Every rank participating in a collective must call collectives in compatible order.
- Nonblocking communication is useful only when work can overlap and buffers are not reused too early.
- Timing should usually include a barrier or another method that accounts for the slowest rank.
- A program that scales within one node may behave differently across the network.

## Exercise

Implement a distributed dot product:

1. divide vectors across ranks;
2. compute a local dot product;
3. combine partial values with `MPI_Reduce`; and
4. compare the result with a serial reference.

Measure strong and weak scaling. Record ranks per node and explain when communication begins to dominate.
